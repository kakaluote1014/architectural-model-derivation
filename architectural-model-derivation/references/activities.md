# 人物活动与空间流线（v0.1.1）

人物用于说明尺度、到达、穿行、停留与空间联系。先从当前模型和资料选实际入口、走廊、平台、楼梯及活动场所，再写一个适合项目的使用情景；没有资料时可以不加人物。不要把住宅、某种人物数量、树木或生活方式套到所有项目。

## 身份与路径依据

所有人物活动标为**情景示意**，不是实际人群的行为记录。模型中的工作提案家具仍保留工作提案身份。不要把一条可播放的线说成交通、消防或无障碍验算，也不能凭空补造通行开口。需要表达尚未确定的连接时，分成不同情景，明确标注断点与待核对，不让人物穿墙来掩盖缺失。

递归模型变换、源坐标和网格保护沿用核心流程。人物、线、辅助环与标签属于网页演示层，不写回模型。用角色、起点、终点、停留位置和理由组织脚本；按项目需要选行走、上下楼、站立交流、坐下休息，不默认填满所有动作。

## 配置

在项目配置中增加可选 `routes` 数组。每项：

```json
{
  "id": "visitor",
  "name": "访客到达",
  "status": "illustrative",
  "evidence": "当前入口及平台坐标；活动由讲解者设定",
  "actor": {"name": "访客", "heightM": 1.7, "color": "#b17b36"},
  "start": 10, "end": 18,
  "waypoints": [
    {"t": 10, "p": [0, 0.025, 0], "action": "walk", "pose": "stand"},
    {"t": 14, "p": [3, 0.025, 0], "action": "stand", "pose": "stand", "heading": 1.5708},
    {"t": 18, "p": [3, 0.025, 0], "action": "stand", "pose": "stand", "heading": 1.5708}
  ]
}
```

上述数字只说明格式，不是可直接放到任意模型上的路径。坐标为米、Y向上，与模型一致；p的Y是人物脚部基准，建议离实际支承面约0.025m。t与建筑、相机共用一个时间轴；活动区间不得超出总时长。首尾waypoint时间对应start/end，end时人物和轨迹退出。所有时间严格递增。

`action`作用于到下一点的区间，可为 `walk`、`stand`、`talk`、`sit`；`pose`为 `stand` 或 `sit`。重复位置的不同时间表示停留。坐下时使用一个 `action:sit, pose:stand` 的起点，下一点 `pose:sit`，相机留出过渡与观察时间。坐姿朝向、座面高度及脚下位置要对照实际家具检查，不能把人坐在空中。

`heading`为弧度，0朝+Z；可配置停留或坐姿朝向。未指定的行走朝向按路径推算，并在转角短暂转身；位置不平滑切角，以免圆滑曲线穿墙。步幅 `strideM` 可选，默认0.72m，仅控制示意步态。沿踏步中心安排楼梯点并核对平台，Y变化决定上楼/下楼。脚部根据实际网格射线支承调整高度，摆腿、摆臂和两段腿姿态用于示意，不是生物力学或完整接触仿真。

默认行走按路程分配时间，楼梯可更慢。构建器拒绝超过2m/s的路径；这只是防止明显快滑的显示约束，不是通行标准。不要为了套用旧案例时长把长路线压缩成高速移动。人物不用语音。

## 采样核对与交互

```powershell
node <skill>/scripts/check_routes.mjs --model mesh.json --config project.json --out qa/routes.json
```

项目可通过 `routeChecks.supportKinds` 与 `obstacleKinds` 指定输入分类。工具按0.15m路段采样，检查中心线及两侧0.18m在0.38/1.0/1.5m高度的射线阻挡，脚下0.23m范围内是否有网格支承。结果不通过时修改讲解路径或限制该段表达，不能改源模型开口来让测试通过。采样通过也不证明连续人体扫掠净空、扶手安全、完整手脚接触、避碰或合规；查看关键帧与实际播放。

浏览器支持独立人物/流线显隐、活动选择和时间跳转。完整路线以淡虚线表达，已走段以实线显示。楼层展开或打开户内功能示意时，人物和路径暂隐，避免把展开间距当成可行走空间。材质白模切换保留人物、相机、时间与几何。暂停、拖动和跨章跳转必须同时恢复人物位置、腿臂姿态和路径进度。

验收至少覆盖一条行走、一段上下楼和一次停留/坐下（视项目资料可用性），以及无路径资料时控制禁用、桌面与手机、正逆序跳转、人物不被主要构件遮挡及动作停留。实体手机与原生建模软件验证分别记录。
